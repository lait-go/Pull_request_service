Критические проблемы
1. Безопасность
SQL-инъекция в миграциях (migrations/migrate.go:46):
  db.Exec(fmt.Sprintf("CREATE USER %s WITH PASSWORD '%s'", cfg.UserDb, cfg.PasswordDb))
Пароль и имя пользователя вставляются напрямую в SQL. Использовать параметризованные запросы или экранирование.
Отсутствует .gitignore для .env — файл с секретами может попасть в репозиторий.
2. Обработка ошибок
pkg/render/render.go:16 — panic после записи в response:
  panic(err)  // после w.WriteHeader и частичной записи
Это может привести к неконсистентному состоянию. Убрать panic, логировать ошибку.
pkg/http_server/http_server.go:35 — неправильная сигнатура logger.Error:
  logger.Error("failed to close server:", err)  // должно быть (msg, err, args...)
internal/adapters/postgres/postgres.go:35 — используется fmt.Printf вместо логгера:
  fmt.Printf("failed to close DB: %v\n", err)
config/config.go:25,30 — неконсистентные сообщения об ошибках (с заглавной "Error").
3. Graceful shutdown
pkg/http_server/http_server.go:33-37 — используется Close() вместо Shutdown():
  func (s *Server) Close() {      if err := s.HTTPServer.Close(); err != nil {  // Close() обрывает соединения
Нужен Shutdown(ctx) с таймаутом для завершения активных запросов.
cmd/app/main.go:65-68 — нет таймаута для graceful shutdown:
  <-sig  post.Close()  server.Close()  // нет контекста с таймаутом
Проблемы архитектуры и качества кода
4. Неоптимальная структура роутера
internal/controlers/http/router.go:53-73 — каждый роут обернут в отдельный Group() без необходимости:
  r.Group(func(r chi.Router) {      r.Post(options.BaseURL+"/pullRequest/create", ...)  })
Можно регистрировать роуты напрямую или использовать один Group для всех.
5. Логика валидации параметров
internal/controlers/http/get_order.go:92-99 — проверка на пустоту, но затем все равно бинд:
  if paramValue := r.URL.Query().Get("team_name"); paramValue != "" {      // пустой блок  } else {      siw.ErrorHandlerFunc(w, r, ...)      return  }  err = runtime.BindQueryParameter(...)  // бинд происходит в любом случае
Логика избыточна.
6. Конфигурация
pkg/http_server/http_server.go:18 — таймаут захардкожен:
  r = http.TimeoutHandler(r, time.Second*5, "request timeout")
Вынести в конфиг.
config/config.go:25 — при ошибке загрузки .env возвращается пустой Config, что может вызвать панику. Лучше возвращать ошибку без Config.
7. Миграции
internal/adapters/postgres/migrations/migrate.go:46-49 — попытка создать пользователя при каждом запуске:
)
  _, err = db.Exec(fmt.Sprintf("CREATE USER %s WITH PASSWORD '%s'", ...))
Нет проверки существования пользователя, будет ошибка при повторном запуске.
cmd/app/main.go:29-33 — при ошибке миграции приложение продолжает работу:
  if err = migrations.RunMigrate(...); err != nil {      logger.Error("migration failed", err)  } else {      logger.Info("migration completed")  }  // приложение продолжает работу даже если миграция упала
8. Неиспользуемый код
internal/adapters/postgres/create_order.go и get_order.go — закомментированный код. Удалить или раскомментировать.
go.mod — неиспользуемые зависимости (kafka, swagger и др.). Очистить.
9. Несогласованность API логгера
pkg/logger/logger.go:35 — Error принимает err вторым параметром, а Info/Debug — нет:
  func Info(msg string, args ...any)  func Error(msg string, err error, args ...any)  // неконсистентно
Унифицировать сигнатуры.
10. База данных
Нет видимой настройки пула соединений (MaxOpenConns, MaxIdleConns, ConnMaxLifetime).
Нет таймаутов подключения к БД.
11. Другие замечания
cmd/app/main.go:60 — логирование после server.Run(), которое блокирующее:
  if err = server.Run(); err != nil {      return err  }  logger.Info("HTTP server started on URL: " + c.Http.Url)  // никогда не выполнится при успехе
internal/controlers/http/router.go:28 — комментарий на русском в коде. Лучше на английском или в документации.
Отсутствует обработка контекста в AppRun — ctx не используется для отмены операций.
Нет middleware для логирования запросов, recovery, CORS и т.д.
Резюме: основные проблемы — безопасность (SQL-инъекция), отсутствие graceful shutdown, неконсистентная обработка ошибок и закомментированный код. Рекомендую начать с критических пунктов.
